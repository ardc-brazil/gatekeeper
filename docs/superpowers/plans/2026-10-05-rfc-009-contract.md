# RFC 009 — contract between the implementation plans

The RFC (`docs/rfcs/009-tenancies-and-admin.md`) is the spec. This file fixes
the names the three plans share, so each can be written and executed without
the others. Where the RFC is silent, the choice is made here and marked
**(decided here)**; a plan that needs to change one of those edits this file
first.

| PR | Repository | Plan |
|---|---|---|
| A | gatekeeper | `gatekeeper/docs/superpowers/plans/2026-10-05-rfc-009-pr-a-gatekeeper.md` |
| B | datamap-webapp | `datamap-webapp/docs/superpowers/plans/2026-10-05-rfc-009-pr-b-webapp-user.md` |
| C | datamap-webapp | `datamap-webapp/docs/superpowers/plans/2026-10-05-rfc-009-pr-c-webapp-admin.md` |

A merges first. B and C are independent of each other; the files both touch
are listed under *Shared webapp code*.

## Gatekeeper HTTP (PR A produces, B and C consume)

Mounted under `/v1` (the webapp reaches it as `DATAMAP_BASE_URL` + path). JSON
is snake_case both ways. Errors use the existing handlers: `{"detail": "<code>"}`.
Every route answers `400 invalid_request` for a body or query it cannot parse.
Timestamps are ISO-8601 strings with offset.

Auth column:

- **client** — `authenticate` only.
- **self** — `authenticate` + new `authorize_self` (`app/controller/interceptor/authorization.py`):
  `{id}` must equal `X-User-Id`, else `401`; Casbin not consulted.
- **admin** — `authenticate` + `authorize` (Casbin; only `admin`'s `/*` matches `/api/v1/admin/...`).
- **dataset** — `authenticate` + `authorize`, then the service checks owner or
  `write` permission on the dataset (RFC 003), else `403 forbidden`.

Tenancy paths in a URL use the `{path:path}` converter, as `tenancy.py`
already does (`/admin/tenancies/datamap/production/atto/members`). Segments
are sent unencoded **(decided here)**.

### Shared shapes

Every `display_name` in a response is the resolved name — the column, else the
derived title-cased namespace — and is never `null` **(decided here)**.

```
TenancySummary   { path: str, display_name: str, is_default: bool, is_legacy: bool }
UserRef          { id: UUID, name: str }
UserBrief        { id: UUID, name: str, email: str | null }
Page<T>          { items: T[], total_count: int, limit: int, offset: int }     (decided here)
```

`UserRef` and `UserBrief` are shared types, created by PR B **(decided here)**.

`is_default` is `path == "datamap/production/public"`; `is_legacy` is
`path` starting with `datamap/staging/`.

Lists of tenancies are ordered public first, then production by
`display_name` (case-insensitive), then legacy by `path` **(decided here)**.

  id: UUID, tenancy: TenancySummary,

The user-side request shape does not name the deciding admin **(decided here)**.

### Users (changed and retired)

- `GET /users/{id}` and `GET /users/providers/{provider}/{reference}`: shape
  unchanged. `tenancies: string[]` now always contains
  `datamap/production/public`; `roles: string[]` contains `datasets_write` for
  new accounts. **`roles` containing `"admin"` is how the webapp learns a user
  is an admin** — no new field **(decided here)**.
- `POST /users` keeps its body; public and `datasets_write` are always added.
- `POST /users/{id}/tenancies` and `DELETE /users/{id}/tenancies` are removed
  (`404`/`405`).

`GET /datasets/{id}/share` (`ShareStateResponse`) gains:

- `tenancy_invitations: DatasetTenancyInvitation[]` — pending, created from this dataset;
- `can_invite_to_tenancy: bool`;
- `tenancy` (`TenancyAccessResponse`) gains `is_default: bool`, `is_legacy: bool`

Dataset responses (`GET /datasets/{id}`, lists) report the **effective**

**(decided here)**. `POST /datasets` defaults it to `false`.

All **admin** auth. Withdrawn requests never appear here.

| `GET /admin/tenancies/{path:path}/members/{user_id}` | — | `200 RemovalImpact` | `404 tenancy_not_found`, `404 member_not_found` **(decided here)** |
| `POST /admin/tenancies/{path:path}/members` | `{user_id}` | `201 TenancyMember` **(decided here; RFC says bare 201)** | `404 tenancy_not_found`, `404 no_account`, `409 already_member`, `409 public_tenancy_locked`, `409 legacy_tenancy_read_only`, `409 tenancy_disabled` |
| `DELETE /admin/tenancies/{path:path}/members/{user_id}` | — | `204` | `404 tenancy_not_found`, `404 member_not_found`, `409 public_tenancy_locked`, `409 legacy_tenancy_read_only` |
| `DELETE /admin/tenancy-invitations/{id}` | — | `204` (status `withdrawn`, `closed_by` = admin) | `404 invitation_not_found` |
| `GET /admin/users?q=` | `q` ≥ 2 chars trimmed | `200 AdminUserHit[]` (≤ 10, enabled only) | `400 invalid_request` |

There is no separate admin list of invitations: pending invitations come with
`GET /admin/tenancies/{path}/members` **(decided here)**.

```
AdminTenancyRequest {
  id: UUID,
  requester: { id: UUID, name: str, email: str | null, email_verified: bool, orcid: str | null },
  requested_name: str, reason: str,
  status: "pending" | "approved" | "declined",
  kind: "join" | "new",                    # from suggested_tenancy, computed at read time
  suggested_tenancy: TenancySummary | null,
  created_at: str,
  tenancy: TenancySummary | null, created_tenancy: bool,
  decision_message: str | null, decided_by: UserRef | null, decided_at: str | null
}

AdminTenancyRequestDetail = AdminTenancyRequest + {
  requester_tenancies: TenancySummary[],
  suggested_tenancy_members: int | null
}

AdminTenancy {
  path: str, display_name: str, members: int, datasets: int,
  is_default: bool, is_legacy: bool, is_enabled: bool
}

TenancyMember { id: UUID, name: str, email: str | null, since: str, invited_by: UserRef | null }

TenancyMembers {
  members: Page<TenancyMember>,            # ordered by name
  invitations: AdminTenancyInvitation[]    # pending; always [] for legacy and public
}

AdminTenancyInvitation { id: UUID, user: UserBrief, invited_by: UserRef | null,
                         dataset: { id: UUID, name: str } | null, created_at: str }

RemovalImpact { member_since: str, datasets_in_tenancy: int, shared_with_user: int, owned_by_user: int }

AdminUserHit { id: UUID, name: str, email: str | null }
```

The webapp does not call `members` for public; it shows "Everyone · {members}
accounts" from `AdminTenancy.members`. The gatekeeper answers it normally.

`q` on the queue matches the requester's name, email or ORCID iD,
case-insensitively, substring.

### Error codes

`400 invalid_request, tenancy_name_invalid, reason_invalid, namespace_invalid,
display_name_invalid, message_invalid, public_members_cannot_edit` ·
`403 forbidden, not_a_member_of_tenancy` (`POST /datasets` for a non-member;
admins unchanged, A2) · `404 request_not_found, invitation_not_found,
tenancy_not_found, no_account, member_not_found` · `409 request_pending,
request_not_pending, already_member, invitation_pending, tenancy_exists,
display_name_taken, requester_email_unverified, public_tenancy_locked,
legacy_tenancy_read_only, tenancy_disabled` · `429 too_many_requests`.

A removed member's dataset call answers `401` with a `detail` that **starts
with** `unauthorized_tenancy` (the existing message carries a suffix); the
webapp matches the prefix.

### Validation rules both sides apply

- `namespace`: `^[a-z0-9-]+$`, 2–63 characters, not `public`.
- `display_name`: 1–64 characters trimmed; unique among enabled production
  tenancies, case-insensitively.
- `tenancy_name` 1–128, `reason` 1–1000, `message` 0–1000, all trimmed.

## Webapp server-side clients

camelCase TypeScript, calling the gatekeeper through `lib/rpc.ts`
(`axiosInstance`). Each throws the Axios error on a non-2xx so the BFF forwards
status and `detail`. Gatekeeper response types live in `types/GatekeeperAPI.ts`
in snake_case, named as the shapes above (`TenancySummary`, `TenancyRequest`,
…; `Page<T>` as `GatekeeperPage<T>`) **(decided here)**.

Self and admin calls send only `X-User-Id` (`{ headers: { "X-User-Id": uid } }`,
as `claimInvitations` does): these routes span tenancies and an account may
have none selected. Dataset calls use `buildHeaders(context)` like the rest of
`lib/share.ts`.

## BFF routes

Responses pass the gatekeeper JSON through unchanged (snake_case); browser
bodies are camelCase **(decided here)**. A route that forwards a gatekeeper
detail code uses `accountHandler` (`lib/accountRoute.ts`), not `bffHandler`,
because `bffHandler` rewrites `401`/`403`/`404` details; other routes forward
the gatekeeper status and `{detail}` through `bffHandler`.

The user and the actor always come from the NextAuth token. The browser sends a
user id only for **the target** of an action: the invitee in B (taken from
`ShareLookup.user.id`) and the member an admin adds or removes in C.

Chains: B uses `bffRouter()` (`authOnlyChain`) for its user routes, so an
account with zero tenancies reaches them, and the same router as
`share/candidates.ts` for the dataset routes. C adds `adminChain` in
`lib/middlewareChain.ts` (`requestLogging`, `auth`, `adminOnly`) and
`adminBffRouter()` in `lib/bffRoute.ts`. `adminOnly` answers
`404 {detail: "not_found"}` when `token.admin !== true`, so the area does not
reveal itself **(decided here)**; the gatekeeper's Casbin check is the
authority.

## NextAuth session (B produces; C consumes it)

- `hydrateWithUserInfo` sets `token.admin = Array.isArray(user.roles) && user.roles.includes("admin")`;
  the session callback sets `session.user.admin = token.admin === true`.
  `types/next-auth.d.ts` gains `admin: boolean` on `Session.user`.
- Populated on sign-in and on every `update()` (the `jwt` callback already
  re-reads the user on `trigger == "update"`). No `TOKEN_VERSION` bump: a token
  without `admin` reads as `false` until its next refresh **(decided here)**.
- Page gate: `auth = { admin: true }` on each admin page; `RequireSession`
  renders the not-found page when `session.user.admin !== true`. Admin pages
  use `LoggedLayout tenancyOptional`.

## Tenancy refresh in the session (B)

- Accept an invitation → `update()`, `setTenancySelected(tenancy.path)`,
  `router.push(ROUTE_PAGE_HOME)`.
- Latest entry of `/api/tenancy-requests` turns `approved` → `update()` and
  offer "Switch to {display_name}".
- `/app/tenancy` compares `GET /api/tenancies` paths with
  `session.user.tenancies` and calls `update()` when they differ.
- A `401` whose `detail` starts with `unauthorized_tenancy` → clear the selected
  tenancy, `update()`, go to `ROUTE_PAGE_TENANCY_SELECTOR`.
