# RFC 008 — contract between the implementation plans

The RFC (`docs/rfcs/008-email-password-authentication.md`) is the spec. This
file fixes the names the four plans share, so each can be written and executed
without the others.

## Gatekeeper HTTP (PR 1 produces, PRs 2 and 3 consume)

Mounted under `/v1` (the webapp reaches it as `DATAMAP_BASE_URL` + path). JSON
bodies are snake_case. Errors use the existing handlers: `{"detail": "<code>"}`.

| Verb and path | Auth | Request | Success | Errors (`detail`) |
|---|---|---|---|---|
| `POST /auth/sign-up` | client | `{name, email, password}` | `202 {challenge_id}` | `400 invalid_name`, `400 invalid_email`, `400 invalid_password` |
| `POST /auth/sign-up/{challenge_id}/confirm` | client | `{code}` | `200 {user_id}` | `400 code_invalid`, `400 code_expired`, `400 code_attempts_exceeded`, `404 challenge_not_found`, `409 email_belongs_to_another_account` (disabled account) |
| `POST /auth/email-verifications` | client | `{orcid, email, name}` | `202 {challenge_id}` | `400 invalid_orcid`, `400 invalid_email`, `400 invalid_name` |
| `POST /auth/email-verifications/{challenge_id}/confirm` | client | `{code}` | `200 {user_id}` | as above, plus `409 email_belongs_to_another_account` |
| `POST /auth/challenges/{challenge_id}/resend` | client | — | `202` | `429 resend_too_soon`, `404 challenge_not_found` |
| `POST /auth/login` | client | `{email, password}` | `200 {user_id}` | `401 invalid_credentials` (every failure) |
| `POST /auth/password-reset` | client | `{email}` | `202` | — (always 202) |
| `POST /auth/password-reset/confirm` | client | `{token, password}` | `204` | `400 token_invalid`, `400 invalid_password` |
| `PUT /users/{id}/password` | client + self (`{id}` == `X-User-Id`) | `{current_password, new_password}` | `204` | `401 invalid_credentials` |

Every route above answers `400 invalid_request` (no echo of the input) for a body it cannot parse.

Sign-up and email verification always return a `challenge_id`, including when
the hourly cap suppressed the email; such a challenge answers `400 code_invalid`
to every code.

User responses (`GET /users/{id}`, `GET /users/providers/{provider}/{reference}`)
gain two fields:

- `email_verified_at`: ISO-8601 string or `null`
- `has_password`: boolean

Self-access: `GET /users/{id}` and `PUT /users/{id}/password` skip Casbin when
`{id}` equals `X-User-Id`, so an account with no role can read itself and change
its own password. No new Casbin rows.

## Webapp server-side client (PR 2 produces in `lib/account.ts`)

camelCase TypeScript, calling the gatekeeper through `lib/rpc.ts`. Each throws
the Axios error on a non-2xx so the BFF can forward status and `detail`.

```ts
signUp(input: { name: string; email: string; password: string }): Promise<{ challengeId: string }>
confirmSignUp(challengeId: string, code: string): Promise<{ userId: string }>
requestEmailVerification(input: { orcid: string; email: string; name: string }): Promise<{ challengeId: string }>
confirmEmailVerification(challengeId: string, code: string): Promise<{ userId: string }>
resendChallenge(challengeId: string): Promise<void>
login(email: string, password: string): Promise<{ userId: string }>
requestPasswordReset(email: string): Promise<void>
confirmPasswordReset(token: string, password: string): Promise<void>
changePassword(userId: string, currentPassword: string, newPassword: string): Promise<void>
```

`requestEmailVerification` and `confirmEmailVerification` are added by PR 3, in
the same file.

## BFF routes (`pages/api/account/*`)

The browser never sends an ORCID iD or a user id; those come from the NextAuth
token on the server. Every route forwards the gatekeeper status and
`{detail}` unchanged.

| Route | PR | Chain | Body from browser |
|---|---|---|---|
| `POST /api/account/sign-up` | 2 | public | `{name, email, password}` |
| `POST /api/account/sign-up/[challengeId]/confirm` | 2 | public | `{code}` |
| `POST /api/account/challenges/[challengeId]/resend` | 2 | public | — |
| `POST /api/account/password-reset` | 2 | public | `{email}` |
| `POST /api/account/password-reset/confirm` | 2 | public | `{token, password}` |
| `PUT /api/account/password` | 2 | `authOnlyChain` | `{currentPassword, newPassword}` |
| `POST /api/account/email-verifications` | 3 | `pendingOnlyChain` | `{email}` |
| `POST /api/account/email-verifications/[challengeId]/confirm` | 3 | `pendingOnlyChain` | `{code}` |

## BFFAPI methods (`gateways/BFFAPI.ts`)

```ts
signUp(input: { name: string; email: string; password: string }): Promise<{ challengeId: string }>   // PR 2
confirmSignUp(challengeId: string, code: string): Promise<void>                                      // PR 2
resendChallenge(challengeId: string): Promise<void>                                                  // PR 2
requestPasswordReset(email: string): Promise<void>                                                   // PR 2
confirmPasswordReset(token: string, password: string): Promise<void>                                 // PR 2
changePassword(currentPassword: string, newPassword: string): Promise<void>                          // PR 2
requestEmailVerification(email: string): Promise<{ challengeId: string }>                            // PR 3

```

Errors reject with the Axios error; callers map `response.data.detail` through
`accountErrorMessage(detail)` in `contants/AccountConstants.ts`.

## Shared components and constants (PR 2 produces, PR 3 reuses)

- `components/Account/CodeInput.tsx`:
  `CodeInput({ value, onChange, onComplete, disabled, invalid }: { value: string; onChange: (value: string) => void; onComplete: (code: string) => void; disabled?: boolean; invalid?: boolean })`
- `components/Account/VerificationCodeForm.tsx`:
  `VerificationCodeForm({ email, onSubmit, onResend }: { email: string; onSubmit: (code: string) => Promise<void>; onResend: () => Promise<void> })`
  — owns the error display and the 90-second resend countdown.
- `contants/AccountConstants.ts`: `PASSWORD_MIN_LENGTH = 10`,
  `PASSWORD_MAX_LENGTH = 128`, `CODE_LENGTH = 6`, `RESEND_COOLDOWN_SECONDS = 90`,
  `accountErrorMessage(detail?: string): string`.
- `contants/InternalRoutesConstants.ts`: `ROUTE_PAGE_FORGOT_PASSWORD = "/account/forgot-password"`,
  `ROUTE_PAGE_RESET_PASSWORD = (token: string) => "/account/reset-password/" + token` (PR 2),
  `ROUTE_PAGE_CONFIRM_EMAIL = "/account/confirm-email"` (PR 3).

## NextAuth token (PR 3)

- `TOKEN_VERSION = 2` exported from `pages/api/auth/[...nextauth].ts`; every
  issued token carries `token.v`.
- `token.pending?: { orcid: string; name: string; emailHint?: string }`, set
  when an ORCID sign-in finds no account or an account with
  `email_verified_at === null`; such a token has no `uid`.
- `session.user.pending: boolean` exposed to the client.
- `lib/middlewareChain.ts`: the existing `auth` step requires `token.uid`;
  `pendingOnlyChain` requires `token.pending` and no `uid`.
